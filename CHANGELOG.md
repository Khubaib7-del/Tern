# Changelog

All notable changes to Tern are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Tern has no released versions yet; once it does, versions will follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added (PR #35)

- **Run checkpoints and resume** (`tern_agent::checkpoint`, GPUI-free): a research run saves its state to `<data>/checkpoints/<chat>.json` (versioned JSON, written atomically, one per chat, removed when the run answers). Quick turns save at the start and after every tool result; deep research saves when the plan is approved, after each worker's reads, after each worker's notes, when a worker ends, and before the answer, keeping each read page's text cut to what a worker is shown. `ChatSession::resume_run` picks a stopped, crashed, or force-quit run up: a quick turn goes on with its conversation so far; a deep run keeps its approved plan (not asked again), finished workers' notes, and unfinished workers' pages and rounds, so no finished worker runs again and no page is read again. Budgets count the tokens used before the stop. These are not the Git screen's checkpoints, which are commits of the vault. Events `run.resumed` and `checkpoint.failed`; turn ends carry `resumable`.
- **Live steering** (`tern_agent::steer`, `tern_research::steer`): a `Steering` inbox per chat; notes sent while a run goes are taken in at the next safe point and logged as `steer.received` and `steer.applied` (with what was done, or why not). A quick turn's model reads the note before its next step. A deep run reads `drop sub-question 3`, `add: cost comparison`, `redirect 2: …`, and anything else as guidance for every notes call still to come and the answer; a dropped worker is stopped with its notes kept, an added one gets a slice like the others (the run's budget grows by it, and the log says so), a running worker takes a redirect as its next search at its next round. A note that arrives while the answer is being written is logged and not applied. Notes from other processes arrive through `<data>/steer/<chat>.txt`.
- **Watcher** (`tern_agent::watch`, `tern_research::watch`): questions on watch live in `<data>/watches.json` with an interval (hourly, daily, weekly, `12h`, `3d`, `2w`). A run is a new chat (a quick turn, or deep research with the plan run as drafted), then the claim checks and report, then a diff against the last report: new and gone sources (matched by URL), changed verdicts (claims matched by their content words), new and dropped claims. No operating-system scheduler: the desktop app runs due watches while it is open, and `tern watch run` from the terminal.
- **Ledgers** (`tern_research::ledger`, `tern_agent::ledger`): from the event log, a source ledger (each URL a search returned or a worker picked: read live, read from the cache, skipped for robots.txt, budget, duplicate, policy, or not picked, or failed, per worker) and a budget ledger (tokens in and out, pages, searches, and time since the lane's previous step, per step, with totals for the run and each worker against its slice). Searches log their hits, and deep workers log the results they leave unread (`sources.skipped`). Both are in the run report (Markdown and JSON, `ledger`), with the steering notes and where a resumed run picked up.
- Terminal: `tern resume [chat] [--list] [--discard] [--json]`, `tern steer <chat> <note>`, `tern watch add|list|rm|run`, `tern ledger [chat] [--turn N] [--json]`; `tern research --deep` takes steering notes typed while it runs and prints how to resume it.
- Desktop: Enter in the composer while a run goes sends a steering note (a hint line says so; the run panel's Summary lists each note and what it did); a **Resume** banner over the composer for a chat whose run stopped (with Dismiss); a **Ledger** view in the run panel (every URL with its site's logo, fate, and reason, then each lane's tokens, pages, searches, and time against its slice); a **Watches** list in the sidebar and a Watches screen (interval, next run, Run now, Open last run, remove, and what changed with source logos and verdict glyphs); an eye under each answer puts its question on watch daily.

### Added (PR #34)

- **Research plans** (`tern_research::plan`, GPUI-free and tested offline): for a deep research request the model drafts a typed, serialisable `ResearchPlan`: 2 to 5 sub-questions (6 at most), each with what to look for, 1 to 3 searches, the expected source types (papers, docs, news, reference, official, data, forums, any), and a share of the budget. Replies are read leniently (fenced or wrapped JSON, a bare list, loose field names, `"40%"` shares); one that is not a plan falls back to Tern's own split (the parts of `A vs B`, a list of questions, or background, evidence, and limits). The run's budget (240k tokens, 24 pages, 600 s by default) is split by share with largest remainder, floors of 4,000 tokens and one page, and time sized for the workers that run side by side. A preflight token range is shown with the plan.
- **Plan approval**: the plan is put to the user before anything is searched or read: **Approve** (run as drafted), **Edit** (reword or drop sub-questions, then **Run**), **Skip plan** (one worker on the whole question), or **Cancel**. Events `plan.drafted` and `plan.answered` (with `edited`).
- **Parallel workers** (`tern_agent::deep`): each sub-question runs as a worker, up to 3 at once (`deep_workers` in preferences, 1 to 6). A worker searches its planned queries, reads up to 3 new pages per round through the shared Tern Crawl reader (robots.txt, per-host pacing, page cache), and writes short notes citing its pages; it may ask for one more search. Each keeps to its own slice of tokens, pages, and time (Over budget and Timed out keep the notes so far), every search and read still goes through the policy gate, and each can be cancelled alone (`DeepControl::cancel_worker`) or with the whole run. Only its notes and their pages reach the synthesis. Events `worker.started` and `worker.finished`; its searches, reads, and model calls are logged as usual with a `worker` field.
- **Synthesis**: the workers' notes are merged into one numbering (the same page read by two workers gets one number), one answer is written from them, its citations are renumbered in order of first use with made-up numbers removed, and a `Sources` list is appended. The claim checks and run report then run as after any turn; the report gains the plan and a **Workers** section (sub-question, status, searches, pages of its slice, tokens of its slice, time, pages read).
- `tern research --deep "question" [--workers N] [--yes] [--json]`: shows the plan and asks to run, edit, skip, or cancel it, prints worker progress, then the answer, the verdict tally, and the report's path.
- Desktop: a **Deep research** toggle in the composer (Research harness), a plan card in the transcript (sub-questions with their searches, source types, and shares, the preflight range, Approve / Edit / Skip plan / Cancel; edit mode has a field and a drop button per sub-question and **Run**), and a **Workers** view in the run panel: one row per worker with its status, sub-question, pages read with each site's logo, pages and tokens against its slice, and a cancel button. The working line says "Researching · 2 running · 1 of 3 done".
- `Run` carries a `DeepRun` (plan, plan state, workers) rebuilt from the events, so a reopened chat shows the same workers; `StepKind::Plan` and `StepKind::Worker`.

### Added (PR #33)

- **Claim verdicts** (`tern-research`, GPUI-free and tested offline): after each answer, Tern finds its claims (every sentence with a `[n]` citation; the closing link list is read for which page each number means, never as claims) and checks each against the text Tern Crawl read for the pages it cites. Verdicts: **Supported**, **Partly supported**, **Not supported**, **No source**, each with the quoted evidence passage and an anchor to it (a `#:~:text=` fragment, or `#page=N` for a PDF page). Two paths: the chat's own model judges the best three passages per claim (one call, up to 16 claims, temperature 0), and a deterministic word-overlap check (content words, every number present, negation agreeing) gives the verdict offline and fills in for anything the model does not answer. Seeded fixtures cover supported, misquoted number, contradicted, unrelated, and unreachable sources.
- **Run reports**: each answered turn writes `runs/<chat>/turn-<n>.md` and `.json` in the data folder: the question, plan and steps, every source read with its reader (Tern Crawl), robots.txt result, and cache hit or miss, the claims with verdicts and evidence, model calls, tool calls, tokens and time against the turn's budget, and errors. Built from the event log alone (`tern_agent::report`), so any past turn can be rebuilt.
- `tern report [chat] [--turn N] [--json] [--out FILE] [--list]` prints or exports a report (`last` by default, or a chat id or its start). A turn that was never checked is checked then, by word overlap.
- Desktop: a verdict badge after each checked claim in the answer (click to open that claim in the report), a **Report** view in the run panel (tally, each claim with its verdict glyph, quoted evidence, and its source row with the site's logo; **Open report** and **JSON** open the saved files), and the working line says "Checking 3 claims" while it runs. The TUI logs the check too.
- Events `claims.checking` and `claims.checked` (verdicts, tally, report paths, judge tokens); `read_url` events carry a `crawl` block (reader, robots, cache). `Fetcher::has_cached`.

### Added (PR #32)

- **Tern Crawl** gets its own logo: a snail, because it crawls: cyan-to-blue gradient with film grain, no background, the one Tern mark with colour. Shown on every "Read N pages" row and on Appearance; one-colour `tern-crawl` glyph for tinted contexts; `assets/brand/tern-crawl.svg`, `tern-crawl-mono.svg`, and `tern-crawl-tile.svg` for standalone use. `TERN_READER` stays as an alias of `TERN_CRAWL`.
- PDF text (`tern_crawl::pdf`): web PDFs and attached PDFs are read page by page with `[page N]` markers, hyphenation joined, a title guessed from page one. Password-protected, scanned, and broken PDFs give a plain reason; a parser panic never takes the app down.
- Picture input: `ImageInput` on `ChatMessage`, sent as `image_url` parts (OpenAI-compatible), base64 image blocks (Anthropic), or `inline_data` (Gemini). Attached pictures ride the next message and stay in the chat history so follow-ups can still see them; chips show a picture icon and size.

### Added (phase 6, started early)

- `tern-desktop`: first GPUI window on `gpui-kit` 0.8 (ADR 0006). Title bar with the Research or Study switch, icon rail, chat list, transcript with Markdown answers, working line, inline approvals, composer (Enter sends, Shift+Enter new line, stop), tokens used of the context window, and a run panel. Neutral greys until ADR 0002.
- CI uploads `tern-desktop.exe` and `tern.exe` (release, Windows x64) on every PR as the `tern-windows-x64` artifact.
- `tern-store`: `recent_sessions` and `rename_session`; a chat takes its title from the first message.
- Run panel views: **Summary** (rollup line, pages read, problems), **Detailed** (each step verb first with its target, note, and time), and **Raw** (every logged event with seq, type, time, and its JSON payload on click; filters All, Tools, Approvals, Search). All three read one `tern_agent::run::Run`, built live or from the log on reopen. "N steps" under an answer opens that answer's run.
- `web_search` results carry `query` and `results` in their event meta.
- Attachments: paperclip button (files and folders), drag and drop onto the composer, and long paste. Text over 4,000 characters becomes a **Pasted text** chip. Chips show name, lines or files and characters, and a **Context** or **Prompt** role (click to switch); Prompt attachments are sent first as the user's instructions, Context is marked as material with no instructions to follow. `tern_agent::attach` reads text files, folders (README first, then path order; hidden folders, `.git`, `node_modules`, `target` skipped; symlinks not followed), and `.zip` archives in memory (zips inside zips up to 3 deep). Limits: 8 MB per file, 200k characters per file, 400k per attachment, 500 files. PDFs, images, and Office files are listed as not read yet. Sent messages show their chips, also after reopening a chat.
- `@` references: typing `@` in the composer opens a menu of this message's attachments, sources read earlier in the chat (with their site), and **Attach a file or folder…**. Letters filter in order (`@rd` finds `README.md`); Up and Down move, Enter or Tab picks, Escape closes. `@prompt:name` sends that attachment as instructions and `@context:name` as material, whether picked or typed by hand. Picking a source adds it as a link the model can read again. Logic in `tern_agent::mention` (GPUI-free, tested).
- Message actions: every message and answer has **Copy** (a check confirms it) and **Reply**, which puts a quote bar over the composer; the quote rides ahead of the text in an `<in_reply_to>` block (`tern_agent::reply`, cut to 600 characters) and shows over the sent bubble, also after reopening. Answers also have **Branch**: a new chat, "Branch of …", that starts with a copy of every turn up to that answer (`tern_agent::branch`; the source chat's log is untouched).
- Session tabs: open chats show as tabs over the transcript once there are two or more (close button on each, **+** for a fresh chat). A chat-list row's **Open in new tab** button opens it beside the current one; clicking a row focuses its tab if open, else shows it in the active tab. Branches open in a new tab; archiving a chat closes its tab. Switching is held while a turn runs.
- Responsive layout (`crates/tern-desktop/src/layout.rs`): at 1100 px and wider both side panels sit beside the chat; from 900 px the run panel floats over the chat; under 900 px the sidebar floats too and closes when the window narrows past it.
- Crawler manners (`tern-crawl`): automated reads keep to each site's robots.txt (RFC 9309: the `Tern` group or `*`, longest rule wins, `*` and `$` patterns, a failing file blocks for 10 minutes) and wait the site's Crawl-delay (capped at 10 s) or 500 ms between reads of one host, at most 8 reads at once. Pages are cached by URL (fragment ignored) for 30 minutes in memory and a day on disk under `<data>/cache/crawl`, shared by every chat, quick ask, and the browser; `Cache-Control: no-store` pages are never kept. The built-in browser is a person reading, so it skips robots and pacing. The reader finds the main text Readability-style (paragraph scores, link density, class hints) and drops cookie banners, share bars, sidebars, and comments.
- Design lock (ADR 0002): palette C, Mono & Lichen, with the lichen accent only on focus, selection, the selected harness marker, the context ring, and Scout's lantern; contrast tested in both modes. Bundled IBM Plex Sans, IBM Plex Mono, and Instrument Serif (OFL). Title-bar lockup: mark, TERN, and the harness in italic serif. Twelve Tern glyphs (Research, Study, five verdicts, checkpoint, watcher, steer, branch-reply, tern-crawl) and twelve built-in service logos shown on source rows for known sites. **Scout**: a procedural rig (spring lantern, blinking eyes that follow the work, a scroll that opens to read) in the sidebar's corner, moved only by real run events and sleeping between blinks; reduced motion shows poses without movement. **Appearance** rail item shows the palette, type, glyphs, logos, and every Scout mood for review.
- Git and GitHub for the vault: a **Git** rail item and a title-bar chip (branch and number of changes) open the Git screen. Make the vault a repository, save **checkpoints** (stage all + commit), switch or create branches, set the `origin` remote, **Pull** (fast-forward only) and **Push**, **Open pull request** (GitHub's compare page for a side branch) and **Open on GitHub**, add missing baseline files (README, LICENSE all rights reserved, SECURITY, CONTRIBUTING), see recent checkpoints, and set who commits (name, email, optional `Co-authored-by: Tern` trailer). Tern runs the user's own `git`, so their GitHub sign-in is used; terminal prompts are off so nothing hangs. `tern_agent::git` parses status and log and checks branch names.
- Built-in browser: the **Browser** rail item opens a pane beside the chat (in the run panel's place, floating on narrow windows) with back, forward, reload, and an address bar. Pages open through Tern's reader as clean Markdown with links kept and no scripts run, behind the same network guard as the agent. Citations in answers, source rows, and links inside the pane open there; **Ask about this page** attaches it to the composer, and the globe hands it to the system browser. The reader now keeps links (`Page.markdown`, `Page.links`) and heading levels.
- Editor and vault: the **Editor** rail item opens the vault (a folder of plain Markdown notes, `<data>/vault` or `vault` in preferences, so Obsidian can open it too). Note list with folders, **New note**, text editing that saves 700 ms after typing stops (and on blur or switching), a **Preview** toggle, `[[links]]` (click to open, or create a missing note) and **Linked from** backlinks. Answers get a **Save to vault** action that writes the question, answer, and sources as a note. The agent gets `vault_search` and `vault_read` (read) and `vault_write` (write, approved per call). `tern_agent::vault` keeps every path inside the vault, `.md` only, hidden folders skipped, atomic writes.
- The mic button is shown locked until a transcription model is set up.
- Motion pass (`docs/02-ui-definition.md` §2.7 and §6), on one curve `cubic-bezier(.32,.72,0,1)`: the working line shows the tern mark moving by state (a 2px glide every 2 s while thinking, quick wingbeats while searching or running a tool, a head dip per page read, small beats with streamed text, still and full-strength when it needs you, dim when stopping) next to a phrase with a 1.6 s shimmer ("Searching · 2 queries", "Reading page 3") and elapsed seconds. The sidebar and run panel slide and fade over 200 ms without reflowing; screens fade in; light and dark cross over in 600 ms with every colour token moving at once and a soft circle from the toggle. Reduced motion (`reduced_motion` in preferences or `TERN_REDUCED_MOTION=1`) turns all of it off.
- `assets/brand/tern-mark.svg`: the mark traced to one-colour SVG; the app embeds it.

### Fixed (desktop)

- Icons outside the components' default set (Pencil, Archive, run-panel icons) rendered blank: the app now registers the full Lucide catalog (`AllAssets`, about 750 KB).

### Added (phase 3, in progress)

- `tern-providers`: catalog of 13 providers (11 remote, Ollama and LM Studio local), own adapters for OpenAI-compatible, Anthropic, and Gemini APIs (ADR 0003), model listing with kinds and context windows, a no-token probe, non-streaming chat, and a usage ledger that marks estimates.
- `tern provider list | add | test | models | remove`. `add` reads the key from a hidden prompt, tests it, and saves it to the keychain only if the provider accepts it.
- ADR 0003: own provider adapters.
- `tern-agent` turn loop: bounded by model calls, tool calls, and tokens; every step moves the turn state machine and is written to the event log (memory or SQLite) before the next; repeated identical calls stop as a suspected loop; cancel flag; no silent retry or fallback.
- Policy gate: Allow, Ask, or Deny per effect class; once and session grants scoped to tool and target, session grants expire; deny rules beat grants; approvals recorded as `approval.requested` and `approval.answered`.
- Typed tool registry with JSON Schema input checks, timeouts, and a fenced `tool` block protocol that works on every provider (ADR 0004).
- ADR 0004: turn loop and policy gate.
- `tern ask "question"`: one search, up to 4 pages read in parallel, one model call, then a citation check; prints the answer, numbered sources (clickable in terminals that support links), unreadable pages, and any citation that matches no source. `--json` for the full report. ADR 0005.
- `tern search list/add/test/remove`: Tavily and Brave keys (tested before saving, kept in the keychain) and self-hosted SearXNG.
- `tern-crawl`: network guard (no private, loopback, or link-local addresses; redirects re-checked; 2 MiB cap), HTML-to-text reader, and source icons (built-in glyph ids for known services, favicon otherwise).
- Chat TUI gets `web_search` and `read_url` when a search service is set up; the launch card says which.
- Chat TUI (`tern` or `tern chat [--provider] [--model] [--base-url]`): unboxed transcript, working line with spinner and timer, composer with Shift+Enter and bracketed paste, footer with harness, provider, model, and tokens (`~` when estimated), boxed approval dialog (`y` once, `s` session, `n` no), help on `?`, Esc to stop. Works at 80×24; no hue until the palette decision.
- `tern-agent::ChatSession`: opens provider, model, and a stored session for front ends, so UIs never touch providers, the keychain, or the database.

### Changed

- `SecretString` moved to `tern-core` so providers never depend on the platform crate.
- `UsageDelta.cost_micros` is optional: no cost is shown until it is known.
- Turn state machine: a tool request rejected before the gate (unknown tool, bad input) moves straight to `RecordResult`.

### Added (phase 2, done)

- Cargo workspace with all eleven crates; dependency rules from `docs/03-architecture.md` enforced by a test that reads every manifest.
- `tern-core`: prefixed ULID IDs, `Q12` / `Q12.3` message references, effect classes, the versioned event envelope, the turn state machine with safe pause and resume, and the secret redactor.
- `tern-platform`: app data paths (`TERN_HOME` override), disk space, and the `SecretStore` trait with Windows Credential Manager. Other OS keychains report as unsupported until phase 12.
- `tern-store`: SQLite schema v1 for projects, sessions, and the append-only event log (redacted on append, update and delete blocked by triggers, replay from any sequence number).
- `tern doctor` (`--json` too): keychain round trip, data directory, disk space, database integrity, in plain language.
- Windows CI: fmt, clippy with warnings denied, tests, and `tern doctor`.
